# Technical Audit Specification: Issue Accumulation Schema (dimension_audit_spec.md)

This document defines the generic JSON payload schema for reporting and accumulating failure logs generated by auditing a target file against a companion, dimension-specific audit specification.

---

## A. Output Payload Blueprint

All compiled audit failures must be accumulated into a single JSON array, conforming to the following schema:

```json
[
  {
    "id": "<unique_id_formatted_as_category_dimension_index>",
    "targetFile": "/<path_to_target_file>",
    "auditDimension": "<active_audit_dimension_name>",
    "strategy": "<active_audit_strategy>",
    "findingType": "<mece_finding_category>",
    "location": "<structural_location_or_context_within_target_file>",
    "constraintReference": "/meta/<path_to_active_audit_dimension_spec_file>.md#<section_anchor>",
    "description": "<clear_objective_explanation_of_how_the_target_content_deviates_from_the_referenced_constraint>",
    "remediation": "<actionable_instructions_outlining_the_specific_adjustments_required_to_resolve_the_issue>"
  }
]
```

---

## B. Field Specifications & Structural Constraints

| Field | Type | Required | Allowed Values / Formats | Description |
| :--- | :--- | :---: | :--- | :--- |
| `id` | String | Yes | `^[A-Z]{3}-[A-Z]{3}-\d{2}$` | Format: `CATEGORY-DIMENSION-INDEX`. |
| `targetFile` | String | Yes | `^/.+$` | Workspace-relative path to the file being audited. |
| `auditDimension` | String | Yes | Free-form string | The active audit dimension that failed. |
| `strategy` | String | Yes | `Affirmative Verification`, `Adversarial Refutation` | The evaluation strategy used. |
| `findingType` | String | Yes | `Errors and Flaws`, `Discrepancies`, `Omissions and Blindspots`, `Ambiguities and Vagueness`, `Short-Sightedness` | The category of technical issue. |
| `location` | String | Yes | Free-form string | Specific structural context within the target file. |
| `constraintReference` | String | Yes | `^/meta/.+_spec\.md(#.+)?$` | Link to the violated constraint spec file. |
| `description` | String | Yes | Free-form string | Objective explanation of how the content deviates from constraints. |
| `remediation` | String | No | Free-form string | Actionable instructions detailing how to resolve the issue. |

---

## C. Payload Integrity Invariants

* **Identifier Uniqueness**: Every issue object in the array must have a unique `id` value.
* **Path Validity**:
  - `targetFile` must point to an existing file in the workspace.
  - `constraintReference` must resolve to an active spec file and section under `/meta/`.
