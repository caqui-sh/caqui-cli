# Technical Audit Specification: Audit Issues Schema (audit.spec.md)

This document defines the generic JSON payload schema for reporting compiled audit issues generated by auditing target scope references (conforming to a base specification designed under [**Base Specification Auditability rules**](audit-meta/base_spec_auditability.meta.md)) against a companion audit specification under any active auditing mode.

---

## A. Output Payload Blueprint

All compiled audit issues must be collected into a single JSON array, conforming to the following schema:

```json
[
  {
    "issueId": "<unique_issue_identifier>",
    "issueLocation": "<structural_location_or_context_within_target_scope_references>",
    "issueDescription": "<clear_objective_explanation_of_how_the_target_content_deviates_from_the_referenced_constraint>",
    "issueRemediation": "<actionable_instructions_outlining_the_specific_adjustments_required_to_resolve_the_issue>"
  }
]
```

---

## B. Field Specifications & Structural Constraints

| Field | Type | Required | Allowed Values / Formats | Description |
| :--- | :--- | :---: | :--- | :--- |
| `issueId` | String | Yes | Free-form string | Unique identifier for the compiled issue. |
| `issueLocation` | String | Yes | Free-form string | Specific structural context within target scope references. |
| `issueDescription` | String | Yes | Free-form string | Objective explanation of how the content deviates from constraints. |
| `issueRemediation` | String | No | Free-form string | Actionable instructions detailing how to resolve the issue. |

---

## C. Payload Integrity Invariants

* **Identifier Uniqueness**: Every issue object in the array must have a unique `issueId` value.

---

## D. Dimension Types & Reporting Model

To execute an audit, constraints are evaluated across two types of dimensions, which dictate how issues are captured and reported in the payload:

* **Terminal & Atomic Dimensions**: These represent non-divisible, independent properties (e.g., Expression Brevity, Expression Precision, Reader Accessibility). Each infraction against a terminal dimension constraint generates a separate, distinct audit issue object in the array.
* **Composite & Entangled Dimensions**: These represent layered properties composed of multiple underlying terminal dimensions that share a mutual trade-off or dependency (e.g., Information Fidelity, which entangles Expression Precision and Expression Brevity).
  - **Singular Entangled Issue**: When an infraction occurs across entangled constraints, it is evaluated holistically from the entangled perspective. Rather than logging a collection of separate terminal atomic issues (e.g., one for wordiness and one for missing detail), the auditor compiles and reports a **singular entangled issue** representing the overall trade-off failure or imbalance.
